# กล่องจดไอเดีย (Idea Inbox) — เอกสารออกแบบ

วันที่: 2 ต.ค. 2569 · ส่วนหนึ่งของขั้น 3 (กลุ่ม B)

## เป้าหมาย

ให้ Owner จดไอเดียบอท/พล็อตได้ทันทีโดยไม่ต้องสร้างผลงาน เก็บไว้ที่เดียว ผูกกับงานไหนก็ได้
และมี **วันเวลาที่จด** ที่เชื่อถือได้ เผื่อต้องยืนยันว่าคิดไอเดียนี้ไว้ตั้งแต่เมื่อไหร่

## สิ่งที่ Owner ตกลงไว้

- แบบ C: มีกล่องรวม และย้ายไอเดียเข้างานไหนก็ได้
- ไอเดียของงานแสดงทั้งในหน้ารายละเอียดและในฟอร์มแก้ไข (ข้อมูลชุดเดียวกัน)
- ไอเดียเป็นข้อความอย่างเดียว · สถานะ รอใช้ / ใช้แล้ว / ทิ้ง
- มีวันเวลาที่จด แก้ไม่ได้ · แก้ข้อความแล้วเก็บประวัติข้อความเดิมพร้อมเวลา
- เห็นเฉพาะ Owner เท่านั้น
- ตัดออกจากรอบนี้: แนบรูป/ลิงก์, ปุ่มสร้างผลงานจากไอเดีย, ตารางคำเรียก/สรรพนาม

## หน้าตา

1. **กล่องรวม** — เมนูบัญชี → "💡 กล่องไอเดีย" เปิดหน้าต่าง:
   - ช่องพิมพ์ + ปุ่ม "จด" (Enter = จด, Shift+Enter = ขึ้นบรรทัดใหม่)
   - แถบกรอง: รอใช้ (ค่าเริ่มต้น) · ใช้แล้ว · ทิ้ง · ทั้งหมด
   - แต่ละไอเดีย: ข้อความ · "จดเมื่อ …" · "แก้ไขล่าสุด …" (ถ้ามี) · ปุ่มสถานะ · "ย้ายไปงาน…" ·
     ป้ายชื่องานที่ผูก (กดแล้วเปิดงาน) · ✏️ แก้ · 🕘 ประวัติ (ถ้าเคยแก้) · 🗑 ลบ (ถามยืนยัน)
2. **หน้ารายละเอียดงาน** (Owner เท่านั้น) — กล่อง "💡 ไอเดียของงานนี้" แสดงเฉพาะไอเดียที่ผูกกับงานนั้น
   จดใหม่ตรงนี้จะผูกกับงานนี้อัตโนมัติ
3. **ฟอร์มแก้ไขงาน** — แท็บใหม่ "ไอเดีย" (เฉพาะงานที่สร้างแล้ว) ใช้ส่วนประกอบเดียวกับข้อ 2
   บันทึกทันทีแยกจากการบันทึกงาน

บันทึกไม่สำเร็จ: ข้อความยังอยู่ในช่อง และขึ้นข้อความไทยบอกสาเหตุ (เน็ต / ล็อกอินหมดอายุ / ยังไม่เชื่อม Drive)

## ข้อมูล

ไฟล์ส่วนตัว `cxl-owner-ideas.json` ในโฟลเดอร์เดียวกับไฟล์ติ๊กกำหนดการคอลแลป (Drive ของ Owner)

```ts
interface Idea {
  id: string;                 // UUID, สร้างที่เซิร์ฟเวอร์
  text: string;               // 1–4000 ตัวอักษร
  status: 'waiting' | 'used' | 'dropped';
  workId: string | null;      // asset_… หรือ null = ยังไม่ผูกงาน
  createdAt: string;          // ISO, เซิร์ฟเวอร์ประทับตอนจด, ไม่มีวันเปลี่ยน
  updatedAt: string;          // ISO, เปลี่ยนเมื่อแก้ข้อความ/สถานะ/งาน
  history: Array<{ text: string; replacedAt: string }>; // ข้อความก่อนถูกแก้, เก่าสุดก่อน, เก็บสูงสุด 50
}
interface IdeaFile { version: 1; ideas: Idea[] } // สูงสุด 2000 ไอเดีย
```

กฎ:
- `createdAt` และ `id` เซิร์ฟเวอร์เป็นคนกำหนด ไม่รับค่าจากเบราว์เซอร์
- แก้ข้อความ: ข้อความเดิมย้ายเข้า `history` พร้อม `replacedAt` = เวลาเซิร์ฟเวอร์
- "ทิ้ง" = เปลี่ยนสถานะ ไม่ลบ · "ลบ" = เอาออกจากไฟล์จริง
- ไฟล์อ่าน/เขียนได้เฉพาะ Owner ที่ล็อกอิน (คุกกี้ session + CSRF แบบเดียวกับไฟล์ติ๊ก) ไม่เคยถูกส่งไปหน้าสาธารณะ
- Google Drive เก็บประวัติเวอร์ชันของไฟล์เองอยู่แล้ว (หลักฐานเวลาจากฝั่ง Google)

## ฝั่งเซิร์ฟเวอร์

ใช้ endpoint เดิม `api/cxl/collab-progress.ts` เพิ่ม `?store=ideas` (Vercel Hobby จำกัด 12 functions,
ตอนนี้ใช้ 11 — ไม่เพิ่มไฟล์ใหม่ใน `api/`) แยกโค้ดอ่าน/เขียนไฟล์ JSON ใน Drive ออกมาเป็น
`src/server/cxlOwnerFiles.ts` ให้ทั้งไฟล์ติ๊กและไฟล์ไอเดียใช้ร่วมกัน ส่วนกฎของไอเดียอยู่ใน
`src/server/cxlIdeas.ts` (pure functions, ทดสอบได้)

- `GET ?store=ideas` → `{ ok, data: IdeaFile }`
- `POST ?store=ideas` body เป็นคำสั่งเดียว:
  `{ op: 'add', text, workId? }` · `{ op: 'edit', id, text }` · `{ op: 'status', id, status }` ·
  `{ op: 'move', id, workId | null }` · `{ op: 'delete', id }`
  เซิร์ฟเวอร์อ่านไฟล์ล่าสุด → ใช้คำสั่ง → เขียนกลับ → ตอบไฟล์ทั้งไฟล์ (จดจากสองแท็บพร้อมกันไม่ทับกันง่าย)
- ตรวจ: text ตัดช่องว่างหัวท้ายแล้วต้องไม่ว่างและไม่เกิน 4000 · workId ต้องเป็นรูปแบบ `asset_…` ·
  id ต้องมีอยู่จริง (ไม่งั้น 404) · เกินจำนวนสูงสุด → 409

## การทดสอบ

- `cxlIdeas` : add ประทับเวลา/สร้าง id เอง, edit เก็บ history, status/move/delete, ตรวจข้อมูลผิด, จำนวนสูงสุด
- endpoint: ต้องล็อกอิน, POST ต้องผ่าน CSRF, `?store=ideas` ไม่กระทบไฟล์ติ๊กเดิม
- `IdeaList` logic: กรองตามสถานะ/งาน, ข้อความไม่หายเมื่อบันทึกล้มเหลว
- ลองจริงบน Preview โดย Owner ก่อนขึ้นเว็บหลัก (พร้อมกลุ่ม A)
